# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（需与三个脚本同目录）。

## 文件结构（数据 / 判定 / 界面分离）

- `index.html`：页面结构与样式。
- `data.js`：数据层。localStorage 读写、作品/部件增删改、合拢留档、旧版整件数据迁移。
- `logic.js`：判定层。工序卡点、阴干架位冲突、合拢资格、交付资格重算、看板状态派生；不接触 DOM。
- `ui.js`：界面层。看板与详情渲染、表单与事件；判定只调 `Logic`，变更只走 `Store`。

## 部件工序

一件作品由正板、侧板、纹样条等多块部件组成，每块单独登记 **名称、尺寸、阴干架位（架位 + 上架/下架日期）**，
按 **贴线 → 阴干 → 上金粉 → 完成** 推进，只能顺序前进、可回退；页面逐块显示卡点（架位未登记、缺陷未处理、阴干逾期等）。

## 阴干架位冲突

部件进入阴干前校验架位时段，与其它部件（跨整件）占用区间重叠时拒绝推进，
并提示"谁占着"：作品主题、部件名、架位与占用起止日期。

## 合拢与交付资格

- 合拢前各部件都必须完成；未完成时提示具体部件及当前工序。
- 合拢后若修改**尺寸、胎体或工序**（含工序回退、新增部件），原合拢失效、整件回到待合拢，
  交付资格按新值重新计算；旧合拢记录（含当时快照与失效原因）在"合拢留档"中保存。
- 已合拢即具备交付资格，确认交付后进入"已交付"列。

## 看板状态

部件制作中 / 待合拢 / 已合拢 / 合拢已失效 / 已交付，按部件工序与合拢记录自动派生。

## 保留能力

主题筛选、状态筛选、按交付日期/阴干上架排序、缺陷记录（按部件登记并汇总）、
今日在架阴干与逾期提示、JSON 导出、localStorage 持久化均继续可用。
