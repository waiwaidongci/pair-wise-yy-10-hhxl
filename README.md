# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用。

## 工序模型：整件由部件组成

漆线雕不再按整件笼统推进，而是**按部件（正板、侧板、纹样条……）单独登记、单独推进**：

- 每块部件登记：**名称、尺寸、阴干架位、阴干起止时段**，并按 **贴线 → 阴干 → 上金粉 → 完成** 四段工序推进。
- 页面在看板卡片和详情弹窗中展示**每一块的卡点**：缺陷未处理、架位/时段未登记、阴干未满、架位时段冲突、工序未完成。
- **架位时段冲突**：同架位、阴干占用时段重叠时，两块互相标注"被谁的哪块占着（时段、工序）"，跨作品同样检查。
- **合拢**：合拢前作品下每一块都必须走到「完成」且无卡点，否则「执行合拢」按钮禁用并列出分块卡点；一块完成不再被当成整件可交付。
- **合拢后改动重算**：合拢之后修改任一部件的**尺寸**、作品的**胎体材质**、或任一部件的**工序步骤**，原合拢立即作废，交付资格按新值重新计算；仅更换架位/阴干时段不作废。旧合拢（时间、原因、当时各部件名称/尺寸/工序/架位快照）在「旧合拢记录留档」中可查。
- 缺陷可记在整件上，也可记在单块部件上；合拢后仍有缺陷则不具备交付资格。

## 文件划分（数据 / 判定 / 界面 三层）

- `index.html` — 页面结构与样式。
- `js/data.js` — 数据层：作品/部件模型、种子数据、localStorage 持久化（v2 键，自动隔离旧数据）、增改、工序推进、合拢作废与留档。
- `js/rules.js` — 判定层（纯函数）：部件卡点、架位冲突扫描、作品派生状态、合拢资格、交付资格、关键修改是否作废合拢、筛选与排序。
- `js/app.js` — 界面层：看板五列（贴线 / 阴干 / 上金粉 / 合拢 / 待交付）、三列概览、详情弹窗、全部交互。

## 保留的原有能力

- 主题筛选、状态筛选、按交付日期排序（新增"按阴干起始"排序）。
- 今日阴干中部件、缺陷作品、最近交付三类概览。
- 缺陷登记（新增分部件记录）、流转日志。
- localStorage 持久化、JSON 导出（导出 v2 完整数据：作品、部件、合拢留档）。
